# Первая версия: подготовка данных и диагностика пилота

Первая итерация проекта по анализу государственных закупок
реагентов для ПЦР-диагностики ВИЧ, гепатита B и гепатита C.

Эта версия сохраняется как исторический этап: первоначальный
подход к отбору контрактов, пилотная проверка и выявление
недостатков фильтрации.

## Бизнес-цель проекта

Выявить перспективные сегменты закупок и оценить их объём.

Задача первой итерации — проверить, насколько первоначальный
фильтр позволяет отбирать контракты с целевыми товарами,
прежде чем переходить к итоговой оценке сегментов.

## Данные

Исходные выгрузки содержат сведения о контрактах, включая:

- регистрационный номер;
- предмет закупки;
- дату заключения;
- стоимость контракта;
- заказчика и поставщика;
- наименования товаров;
- коды ОКПД2.

Для пилотной проверки используются сведения об отдельных
товарных позициях, извлечённые из Word-документа.

Исходные данные и результаты обработки не включены
в репозиторий согласно `.gitignore`.

## Первоначальный подход

Первоначальный фильтр объединял текстовые поля контракта:

- `subject`;
- `industry`;
- `subindustry`;
- `product_names`;
- `product_codes`.

Контракт проходил фильтр, если в объединённом тексте
одновременно находились:

1. Признак метода из широкого поискового словаря.
2. Упоминание ВИЧ, гепатита B или гепатита C.

Поисковый словарь первой версии был шире строгого критерия ПЦР:
он также включал общие обозначения амплификации нуклеиновых
кислот, NAT, NAAT, TMA, NASBA и мультиплексных исследований.

Таким образом, первоначальный фильтр формировал кандидатов
для проверки, а не окончательно подтверждённый реестр
целевых закупок.

## Дизайн пилотной выборки

Случайная часть пилота формируется по ячейкам:

- год;
- ценовая страта;
- федеральный округ.

Ценовые страты:

| Страта | Стоимость контракта |
|---|---|
| `lt_1m` | Менее 1 млн рублей |
| `1m_to_5m` | От 1 млн до 5 млн рублей включительно |
| `gt_5m` | Более 5 млн рублей |

Для случайного отбора используются первые две страты.

Параметры пилота:

- доля отбора внутри ячейки — 10%;
- минимальное число контрактов — 2, если размер ячейки позволяет;
- максимальное число контрактов — 15;
- отбор без возвращения;
- фиксированное значение генератора — `SEED = 42`.

Для контрактов дороже 5 млн рублей предусмотрено формирование
отдельного списка для сплошной обработки. Создание этого списка
само по себе не означает, что все крупные контракты уже разобраны.

## Критерий целевой позиции при диагностике

Позиция получает метку `1`, если в её наименовании
одновременно присутствуют:

- явный признак ПЦР;
- хотя бы одна целевая нозология: ВИЧ, гепатит B или гепатит C.

Любые дополнительные нецелевые нозологии не отменяют метку `1`.

Примеры:

| Наименование | Метка |
|---|---:|
| ПЦР ВИЧ | 1 |
| ПЦР гепатит B и гепатит C | 1 |
| ПЦР гепатит C и герпес | 1 |
| ПЦР ВИЧ, гепатиты B/C и другие инфекции | 1 |
| ПЦР герпес | 0 |
| ИФА ВИЧ | 0 |

Признаки не должны переноситься между соседними позициями.

Отсутствие явного ПЦР означает отсутствие совпадения
с этим текстовым правилом, а не самостоятельное установление
фактического метода исследования.

## Результаты диагностики

В проанализированном пилоте:

| Показатель | Значение |
|---|---:|
| Контрактов всего | 277 |
| Контрактов с найденными целевыми позициями | 196 |
| Контрактов без найденных целевых позиций | 81 |
| Доля контрактов без найденных целевых позиций | 29,2% |

Результат относится к обследованному пилоту и применённым
правилам разметки. Он не является автоматически оценкой
доли ошибок во всём исходном реестре.

### Распределение найденных целевых позиций

| Сегмент | Позиций | Контрактов | Сумма по результатам пилотного расчёта, руб. |
|---|---:|---:|---:|
| ВИЧ | 60 | 52 | 37 284 644,23 |
| ВИЧ + гепатит B + гепатит C | 26 | 26 | 17 195 835,72 |
| Гепатит B | 152 | 111 | 9 646 082,12 |
| Гепатит B + гепатит C | 1 | 1 | 31 128,89 |
| Гепатит C | 147 | 95 | 17 658 716,16 |

Один контракт может содержать позиции разных сегментов,
поэтому количество контрактов по строкам таблицы
нельзя складывать как число уникальных контрактов.

Комбинированная позиция учитывается в отдельном сегменте.
Её стоимость не распределяется между нозологиями.

Приведённые суммы характеризуют результаты пилотного расчёта,
а не объём рынка. Их использование в итоговой оценке требует
проверки полноты извлечения, достоверности сумм и дублей.

## Выявленная проблема

Первоначальный фильтр не обеспечивал проверку сочетания
метода и нозологии внутри одной товарной позиции.

Например, контракт мог содержать:

1. Набор для ПЦР-исследования герпеса.
2. Набор для ИФА-исследования ВИЧ.

В объединённом тексте находились и ПЦР, и ВИЧ,
поэтому контракт проходил первоначальный фильтр.
Однако ни одна из этих двух позиций не соответствовала
целевому сочетанию.

Дополнительная сложность: поле `product_names`
может содержать несколько товаров в одном текстовом значении.
Запятые и переводы строк используются как между товарами,
так и внутри их описаний.

## Запуск

Команды выполняются из корневой папки проекта.

Установка зависимостей в активированное виртуальное окружение:

```bash
python -m pip install pandas numpy openpyxl python-docx
```

Подготовка реестра:

```bash
python pilot_v_1/data_preparation.py
```

Формирование пилотной выборки:

```bash
python pilot_v_1/pilot_design.py
```

Извлечение позиций из Word:

```bash
python "pilot_v_1/pilot parser.py"
```

Анализ пилота:

```bash
python pilot_v_1/analyze_pilot.py
```

Отдельный список крупных контрактов:

```bash
python contracts_5m.py
```

Перед запуском необходимо разместить исходные файлы локально
и проверить блоки путей в скриптах. Репозиторий без исходных
выгрузок не содержит всех данных для воспроизведения расчётов.

Повторный запуск может пересоздавать выходные файлы.
Для сохранения исторических результатов следует заранее
сделать их резервную копию.

## Результаты обработки

Подготовка данных формирует:

- предварительно отобранный реестр контрактов;
- распределение генеральной совокупности по ячейкам;
- распределение для случайного отбора;
- перечень контрактов из страты дороже 5 млн рублей.

Отбор пилота формирует:

- номера выбранных контрактов;
- полные сведения о выбранных контрактах.

Анализ пилота формирует:

- позиции с целевой и нецелевой разметкой;
- сведения о контрактах с найденными целевыми позициями;
- отчёт о контрактах без найденных целевых позиций;
- финансовую диагностику;
- сводку по сегментам и выборочным ячейкам.

## Ограничения

- Первоначальный фильтр работает на уровне объединённого
  текста контракта, а не отдельного товара.
- Пилот проверяет отобранные контракты, но сам по себе
  не оценивает релевантные закупки, пропущенные фильтром.
- Отсутствие найденных целевых позиций не доказывает
  их отсутствие при неполной выгрузке.
- Неизвестные суммы нельзя интерпретировать как нулевые.
- Стоимость контракта целиком не равна стоимости
  его целевых позиций.
- Возможные дубли и расхождения сумм требуют отдельной проверки.
- Совпадение суммы позиций со стоимостью контракта
  само по себе не подтверждает полноту извлечения.
- Результаты пилота нельзя напрямую объявлять объёмом рынка.

## Переход ко второй версии

Во второй итерации планируется:

1. Восстановить границы товаров в `product_names`.
2. Использовать количество записей ОКПД2 как ограничение
   при подтверждённом соответствии формату источника.
3. Проверять метод и нозологию внутри одной позиции.
4. Сохранять основания разделения и признаки неоднозначности.
5. Проверить качество на эталонной разметке и новых контрактах.
6. Создать новую выборку и провести ее анализ.

Первая версия сохраняется как документированный этап
выявления проблемы, а не заменяется исправленной реализацией.
